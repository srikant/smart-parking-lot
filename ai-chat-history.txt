2. PROMPTING METHODOLOGY
--------------------------------------------------------------------------------
The interaction was deliberately structured around four practices:

  a) Context-first
     All assignment documents (problem statement, assignment instructions,
     interview guide, and the assignment email) were loaded and acknowledged
     BEFORE any code generation. A detailed candidate background was also
     provided up front so the assistant could calibrate to a senior-engineering
     bar.

  b) Spec-driven prompting
     Prompts reference specific spec sections, constraints, and worked examples
     verbatim rather than paraphrased wishes. Examples:
       - "floating hourly blocks, weekday-only peak detection, partial-overlap
         logic, and progressive rates ($5 / $3 / $2)"  [Spec: Policy 1]
       - "a test proving the spec's exact conflict scenario (weekday 06:30 →
         16:00 picks Early Bird $15 over Standard $31)"  [Spec: Conflict
         Resolution — Best Value Logic]

  c) Verify-first
     Expected fare values were hand-derived block-by-block before the
     corresponding tests were requested. Where the assistant flagged an
     ambiguity, the candidate made an explicit decision and documented it
     rather than letting the AI assume silently.

  d) Incremental, reviewed progression
     One concern per exchange (domain → specials → standard → engine → docs →
     execution). Each phase was reviewed before proceeding. The candidate
     corrected the assistant's output where it was inconsistent (see Judgment
     Log, item 4) and scoped out non-essential artifacts (item 6).
